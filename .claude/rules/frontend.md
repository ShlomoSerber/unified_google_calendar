# Frontend rules

- The frontend is a renderer. It never expands recurrences, never computes conflicts, never stores tokens, never talks to Google. It calls the commands in `docs/02-arquitectura.md` section 5 through `src/ipc/` and renders the payload.
- All CSS values come from `var(--token)` defined in `src/styles/tokens.css`, which is generated by `node scripts/gen-tokens.mjs` from `docs/design/tokens.json`. Never edit `tokens.css` by hand. Never write a literal px, color, font-size, weight, radius or shadow in a component stylesheet. Exception: `0`, `100%`, `auto`, `1fr`, and `calc()` that only combines tokens.
- If a needed token does not exist or is `null`, stop and use the `measure-component` skill. Do not approximate.
- Fonts: only the families declared in `src/styles/fonts.css`. `font-synthesis: none` stays in `base.css`.
- One component per file, PascalCase file name, a `.css` file with the same name next to it, class names prefixed with the component name in kebab-case.
- State: zustand store in `src/state/` holds only UI state (current date, view, selected occurrence, open dialog). Data comes from `get_view` and is refreshed on `calendar:updated`.
- Popups are DOM elements positioned with JS following the measured rules in `docs/04-fidelidad-visual.md` section 8. Never open a second Tauri window.
- No timers in JS except UI animation. Periodic work lives in Rust.
- Keyboard shortcuts, drag and drop, search and Tasks are version 2. Do not add them.
- `npm run lint && npm run typecheck && npm test` must pass before every commit.
